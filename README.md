# Apexle

**Wordle for F1 nerds.** You're shown the anonymised telemetry for one Formula 1
corner — speed, and (by difficulty) throttle and braking — with no track map or labels.
Guess the corner. Each guess is scored Wordle-style against the hidden answer across its
telemetry attributes (min speed, braking distance, corner angle, gradient, gear, lateral
G, direction, DRS), with ▲/▼ arrows pointing you toward the answer. Daily puzzle,
streaks, three difficulties, shareable result grid.

Lives at **apexle.dexo.games**. Built to match the [dexo.games](https://www.dexo.games)
look but kept completely separate (its own repo, build, and deploy) so it can be changed
or removed without touching the main site.

Built with **React + TypeScript + Vite**, fully static (no backend). Real telemetry is
extracted offline via [FastF1](https://github.com/theOehrly/Fast-F1) and bundled as JSON.

## Develop

```bash
npm install     # first time only
npm run dev      # dev server (http://localhost:5173)
npm run build    # type-check + production build into dist/
npm run preview  # serve the production build locally
```

## Project structure

```
public/             Static assets (fonts copied from dexo.games, CNAME, favicon)
data-pipeline/      Python FastF1 extractor (build-time only) — see its own README
src/
  data/             corners.json + circuits.json (generated by the pipeline)
  types/            Corner / Circuit / Difficulty types
  game/
    attributes.ts   THE ATTRIBUTE REGISTRY — enable/disable comparison attributes here
    data.ts         loads the JSON, daily/random corner selection
    useGame.ts       game state machine (daily/practice, guesses, win/lose)
    useStats.ts      per-difficulty streak stats
  lib/              rng (daily seed), compare (scoring), share, storage
  components/       Header, Footer, TelemetryChart, GuessInput, ComparisonGrid,
                    DifficultyToggle, StatsModal, HowToPlayModal, ResultShare, Modal
```

## Telemetry data

Corner data is **pre-computed offline** so the site stays static. See
[`data-pipeline/README.md`](data-pipeline/README.md). In short:

```bash
cd data-pipeline
pip install -r requirements.txt
python extract.py          # the 5 seed circuits (shipped)
python extract.py --all    # fill in the rest of the modern roster
```

The repo ships with 5 circuits seeded (Monaco, Silverstone, Monza, Spa, Suzuka). The full
modern roster (~24 circuits) is already configured — run `--all` to populate it, then
rebuild. Re-running merges into the existing JSON; downloads are cached.

### Turning attributes on/off

Every comparison attribute is declared once in
[`src/game/attributes.ts`](src/game/attributes.ts) with an `enabled` flag. Flip it to add
or drop an attribute everywhere — scoring, the grid, and the share output all read from
that list, and the pipeline always stores **all** attributes, so no data re-run is needed.
Two extras (`entrySpeed`, `duration`) ship disabled — set `enabled: true` to include them.

## Deployment (GitHub Pages → apexle.dexo.games)

Pushing to `main` runs `.github/workflows/deploy.yml`, which builds and publishes `dist/`
to GitHub Pages. `public/CNAME` pins the custom domain.

**One-time setup:**
1. **DNS:** at your domain registrar, add a `CNAME` record: `apexle` → `dexogames.github.io`.
2. **GitHub:** repo **Settings → Pages → Source = "GitHub Actions"**.
3. Push to `main`.
